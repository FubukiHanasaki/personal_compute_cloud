# 第二轮静态安全复查

作者：FubukiHanasaki。日期：2026-11-03（Asia/Shanghai）。

延续上一轮“不用实际测试”的要求，本轮仅阅读源码、分析权限/数据流、运行静态扫描及语法检查。没有启动服务、数据库、Agent、沙箱、模型或浏览器，没有执行回归用例、网络渗透测试或部署。此前的运行结果不代表本轮修改已经实测通过。

## 明确发现与修复

| 范围 | 风险与修复 |
|---|---|
| API Key 权限 | 原 revoke 接口仅检查账号/角色，Owner 的只读 Key 因而可以撤销高权限 Key；jobs:write Key 还可以继续签发同作用域的长期 Key。现在列出、创建、撤销账号密钥统一要求网页登录会话或具有管理员角色的 admin Key；任务 Key 不获得账号密钥管理能力 |
| 凭证撤销时序 | 密钥创建/撤销和节点注册令牌签发在取得数据库变更锁后重新认证，阻止认证后排队、期间凭证已撤销却继续签发新凭证的窗口 |
| 禁用与重新启用 | 原禁用只清理 Web 会话，旧 API Key 在重新启用后恢复可用，未使用的管理员注册令牌仍能注册节点。现在禁用时永久撤销现有 Key、清理会话、使待用注册令牌到期；注册时另行确认签发者仍活跃且具有 Owner/Admin 角色 |
| 未认证请求内存 | 原按列表保留请求分块，再 join；大量极小分块会在达到字节上限前放大内存。改为 bytearray 连续缓冲，使额外开销随正文总字节数增长，保留原请求体上限 |
| Linux Worker 故障 | 原构造在启动子进程后若写 stdin 失败，上层尚未持有 Worker，可能直接报告 stopped。现统一清理部分构造；无法确认清理时抛出 WorkerStopUnconfirmed，保留日志并中止执行；处理进程自行退出与 killpg 的竞态 |
| CSRF 错误处理 | 原字符串常量时间比较遇到非 ASCII 请求头会抛出 TypeError。现在比较编码字节，非法值正常拒绝为 403，安全机制不变 |
| CI 凭证暴露面 | 两个 GitHub Actions 工作流显式设置 contents: read，checkout 不持久化 Git 凭证，降低后续依赖安装和 PR 代码接触仓库写入权限的风险 |

## 数据流复核

- 会话写操作必须校验 CSRF；Bearer Key、节点凭证和注册令牌使用不同表/入口，服务端仅保存摘要。前端使用 HttpOnly Cookie 与内存中的 CSRF，不通过 localStorage 保存长期 Key，也未发现直接插入未转义 HTML 的代码。
- 任务领取受当前用户授权、双层本地/云端策略、模板能力和资源额度限制；过期租约不能上传或完成，取消意图保留，停止确认前不释放原 attempt 的资源。
- 上传只接受受限元数据、大小和校验和；服务端生成不透明存储键，下载复核任务归属、当前 attempt 和有效期。备份归档拒绝路径穿越、链接、重复成员及超量展开；恢复要求空目标并保持停写窗口。
- 子进程启动使用参数列表，无 shell 拼接。运行时、可执行文件、模型和工作流由节点管理员在本地批准；普通 API 用户不能提供执行路径或工作流图。ComfyUI 图片结果采用流式读取并限制大小。
- Windows 延续 AppContainer/Job Object、独立运行时、限定继承句柄、零网络 capability 与停止确认；Linux 计算模板延续 bubblewrap。受管模型的 cgroup 是资源边界，仍运行在节点账号下，不将它表述成与计算沙箱等同的文件/网络隔离。
- 生产 Compose 只有 Caddy 发布端口，Server 非 root、只读根文件系统、删除 capabilities；数据库账号不是超级用户；Agent 验证 HTTPS 且不跟随重定向、不使用环境代理。

## 静态扫描结果

Ruff 的 S 类规则扫描 server/agent，共产生 22 条提示，均逐项结合调用点复核，保留扫描结果于被忽略的 tmp/security-review：

| 规则 | 数量 | 复核结论 |
|---|---:|---|
| S603 | 14 | 子进程参数来自固定探测命令、Agent 批准的执行器、本地运维命令或受控模板；无用户命令入口和 shell=True |
| S607 | 4 | systemctl/systemd-run 为节点账号 PATH 中的本机管理工具；PATH/本地运行环境属于节点管理员信任边界，普通用户不能经 API 修改 |
| S606 | 1 | limit_exec 使用 execv 启动 Agent 构造的固定 bubblewrap 命令；不经 shell，也不将该包装器暴露给用户 |
| S311 | 1 | random 仅用于重连退避抖动，凭证实际使用 secrets；无加密用途 |
| S108 | 1 | /tmp 是 bubblewrap 参数指定的私有 tmpfs，并非向宿主公共目录写固定临时文件 |
| S110 | 1 | 推理停止后读取 future 的异常已由请求线程记录；后续必须检查 future 已完成，并再次停止 error backend，不能靠忽略异常确认停止 |

扫描当前未忽略文件及全部 Git 提交差异：私钥 PEM、AWS Access Key、长 PCC/节点/会话/租约/注册令牌模式没有命中。该启发式扫描不覆盖所有凭证格式，不等于证明仓库绝无秘密。server/agent 的 AST 扫描没有发现直接 eval/exec 调用或 shell=True。

Python AST、Ruff 关键错误规则及变更格式检查、部署 Shell 语法与工作流 YAML 语法检查通过。已准备密钥越权、禁用后旧凭证失效、非 ASCII CSRF、细碎分块内存和 Linux 构造失败的回归用例；按要求未执行。
