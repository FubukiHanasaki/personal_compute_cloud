# 受管内存解耦验收 · 2026-11-04

作者：FubukiHanasaki。

## 实现

`pcc_agent.memory` 提供后端与 Agent 共用的字段类型、配置校验及资源阻塞原因。`Capabilities` 和 `AgentConfig` 增加 `managed_commit_budget_mb`、`managed_available_memory_mb`；沿用 capabilities JSON，不新增迁移。预算不再受物理总量或 compute 分配额度截断，原任务 / 模板进程上限不改变。

调度抽取统一资源占用快照，实际领取与队列原因复用相同判断。受管任务的物理空闲检查不累加可回收服务提交额度，既有 CPU / 显存 / 并发 / 授权 / 策略 / 负载保护保留。活动及待核对任务、启动 / 停止 / 错误服务继续计账；同一任务和服务不重复计账。

Agent 本地准入、预热与模型切换沿用相同内存规则。因物理门槛不足而不能预热时保持 stopped，不声明已启动占用；旧进程停止未确认时拒绝接管。已有同名模型和改变参数的模型都不能跳过物理门槛。热更新预算与门槛不修改模型上下文、KV、视觉或思考配置。

GUI 支持预算和完整 worker 门槛保存，服务端节点详情区分物理内存、计算额度、推理预算及各 worker 门槛。NInfer 校验 / 编辑器允许 `nvfp4` 和 `k8v4`，已有值不替换、不降低精度。用户 API Key 与授权逻辑不变。

本版不兼容旧受管推理配置：启用的 worker 缺少预算或门槛，配置解析 / 心跳明确拒绝。无受管 worker 的 compute / synthetic 节点不强制配置推理预算，其调度仍按原物理资源规则。

## 真实小模型 GPU 验证

本机 RTX 3060 Laptop、6144 MiB 显存。使用已有本地 Ollama / smollm2:135m、ComfyUI / SD1.5 权重及新的 ServiceManager 准入路径，不下载权重、不连接生产环境。

两次测试均上报物理总量 **14869 MiB**、计算分配额度 **512 MiB**，配置独立预算 **32768 MiB**、实际启动门槛 **4096 MiB**，将进程硬上限 **32768 MiB** 原样交给受管后端。Ollama 实际推理用时 32.21 秒，ComfyUI 实际生成用时 15.05 秒；均确认受管进程停止，设备显存回到测试前约 13 MiB。

该验证证明真实受管执行不再被物理总量或计算额度错误拦截。Linux 仍使用 cgroup 内存硬限制，不把它当作 Windows Job 提交限制的实机证明；未加载本次目标 Qwen / NInfer 大模型，也未重复用户的 58 次物理压力试验。
